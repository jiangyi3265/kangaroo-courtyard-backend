# 心愿互助（V87）

本次新增小程序心愿互助分包、平台审核与结算页面、服务端订单和资质流程。UI 使用已确认的深海蓝、亮蓝、柠檬黄配色。

## 入口与页面

- 小程序首页、社区：心愿互助入口；发布页：发布心愿入口；个人中心：我的心愿。
- `pages/wish/index` 广场；`filter` 城市、品类、付费方式、金额区间与排序。
- `detail` 心愿详情与接单确认。
- `publish` 有偿 / 免费发布、图片上传、草稿、费用预览、发布确认。
- `order` 订单进度、双方沟通、交付凭证、完成确认、争议、结算与评价。
- `mine` 我发布的 / 我帮助的；`rules` 费用及品类规则；`credential` 资质与私有收款资料。
- 后台：袋鼠业务 → 心愿互助，组件 `kangaroo/wishes/index`。

## 上线顺序

1. 备份目标库，在 V86 已完成的同一业务库执行 `V87__wish.sql`，确认迁移账本记录 V87。
2. 发布新后端。启动时校验心愿相关表与唯一索引；先发代码、后迁移会被阻止启动。
3. 发布管理后台，为审核 / 财务角色分配 `kangaroo:wish:list`、`kangaroo:wish:edit`。普通角色不会因为新增菜单自动获得审核权限。
4. 发布小程序。心愿页面、组件和背景图位于 `pages/wish` 分包；首页入口无需加载该分包的大图。
5. 有偿功能沿用现有 `kangaroo.pay.mode`、微信商户与证书配置，通过配置的平台商户收款。`off` 会拒绝创建收费订单；`mock` 仅用于既有本地联调环境。正式环境需验收真实支付回调和退款。

## 金额与订单规则

所有金额由服务端以整数分保存。成本价允许 0.01～100000 元，最多两位小数。

例如成本 ¥100.00：加价 ¥1.00，公开展示及发布者支付 ¥101.00；完成后按 ¥101.00 收取 5% 手续费 ¥5.05，服务者净结算 ¥95.95。两项费用各自四舍五入到分。免费订单的全部金额为零，不创建支付订单。

有偿发布先支付，免费发布直接进入审核；审核通过后开放接单。所有心愿由平台审核品类及内容。药品、医疗器械、保健品、活体动物、违禁危险品、人身安全类服务、金融、证件代办、法律服务不开放。食品接单需审核通过的健康证或食品经营许可证；烟酒默认不开放，特殊许可须按城市单独审核并校验服务者资质。

状态：`pending_payment → reviewing → open → accepted → submitted → completed`。发布者在接单前可取消，有偿订单全额原路退款；已接单后由双方申请争议，平台裁定继续履约、全额退款或完成。退款状态分为处理中、失败可重试和完成，不能把排队退款视为已经到账。

完成后生成待打款金额；**此版本采用平台核实收款资料后线下打款、后台登记真实流水的结算方式，不会自动向服务者银行卡转账**。后台登记必须核对净金额、已审核的本人收款资料和唯一流水号。未登记前前台始终显示待打款。免费订单无需资料或打款。

发布、消息发送使用幂等键；接单、完成、打款使用数据库事务与行锁。退款统一先锁支付单再锁心愿；通用支付退款入口不能绕过心愿状态对已结算订单退款。所有审核和资金处理留有审计记录。

资质文件存储在现有 `KgPrivateFiles` 私有目录，只有本人和有权限的后台账号可以取得10分钟有效的签名链接。用户上传图片仍使用现有公开图片服务；详细收件信息应在双方订单沟通中交换，不应放到公开描述。

## 验收与产物

- `WishPricingTest`：金额、舍入、免费零费用、非法输入。
- `WishFlowIT`：独立 MySQL 数据库内验收事务、幂等、抢单、角色越权、资质、争议退款、结算及防止重复打款；测试后清理自己的临时库。
- 回归 `PayCreationIT`、`KgPayRefundReconcileTest`、`KgPayWxTimeTest`。
- 小程序 `scripts/check-wish-ui.mjs`、`check-wish-flow.mjs`：360 / 390px 页面、筛选、图片上传、有偿发布与模拟支付、接单、沟通、交付、确认、收款资料、后台结算登记、评价、免费全流程。
- `scripts/check-wish-admin.mjs`：后台路由权限、订单详情与审核、私有资质查看。
- 验收图在工作区 `artifacts/wish-ui/`，不会被打入小程序或后端。

本地验收使用独立数据库 `kg_wish_full_20261108`、独立 Redis 6387、后端 8087、H5 5187、后台 5188；所有测试付款和打款记录均为隔离环境中的模拟数据，没有真实扣款或转账。生产数据库和已部署应用未被修改。
